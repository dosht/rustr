## Review and execution discipline

Feature owners implement in their existing visible saved sessions and publish actual interfaces before dependent code. The lead decides scope, integration windows, evidence and canonical dispositions; it does not implement product code. The independent test/integration owner alone owns released root manifest/lock/Docker integration and executes generated-artifact, browser, UI/UX and packaged checkpoints on lead authorization. Implementers do not run their own checks or spawn nested agents. Shared files have one writer. Each completed phase receives a bounded Fable medium or Claude review; the book stays last. Local fixtures never establish live model/payment/storage/OAuth acceptance.

Implementation uses OMP, preferring Astra in preserved owner sessions. Advisors use native Codex CLI with Astra and native Claude CLI with Opus, not OMP. Do not reinterpret this as a migration of implementation workers to native CLIs. Existing Opus/Sol/Fable source and review provenance is retained; any later Fable use remains MEDIUM. Independent test execution remains separately owned.

Fable's high review was useful for phone-source corrections, i18next, payment-status coverage and avoiding a needless AI-start route. Its export, auth-boundary, receipt and compatibility-field recommendations are not binding and are resolved above. Measured usage and the subsequent medium-only policy are in `brief.md`; the Claude usage tab remains open.
