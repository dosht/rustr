3. **Feedback and support.** Inspected routers do not supply the source feedback insert or `/api/support`. Add real owned feedback rows and session POST support with owned optional job context, existing Mailer templates/ordering, typed success/failure and erasure inclusion. 4. **Invoices/subscription read composition.** Existing history/admin routes and billing helpers are real, but own invoice context/subscription screen data must include the necessary customer/billing_info/payment facts without making users administrators. Replace direct Supabase realtime only with a small owned refresh transport: recommend visibility-scoped polling of current list/job/line reads, reusing the source 2-second fallback and deduplication by id. ## 3. Exact flow and lifecycle contracts

### 3.1 Files, language and YouTube

Desktop: optional existing YouTube banner, transcription/translation tabs, drop/choose zone or queue, configuration beneath files, add-source menu, then Start. Phone: total duration when files exist, large upload and enabled YouTube buttons, queue/swipe removal, configuration/language sheets, fixed safe-area Start. Only upload and YouTube are enabled workspace sources. No new grammar control, estimate-price UI, generic URL field, Drive/OneDrive login or microphone job source.

For each selected file: preserve the browser measurement order (HTML audio metadata up to 5 seconds, Web Audio fallback up to 100 MiB/10 seconds), create draft with measured duration or null, reconcile current language/target/speaker options, request signed URL, do one PUT with byte progress, and mark uploaded only for HTTP 200. Keep file handles outside serialized Rust state, indexed by its stable local id. Send Blob/File directly rather than copying the full media through JSON/wasm; this is a representation/memory improvement, not a new upload-size limit or retry policy. Dispose object URLs and decoder resources on completion/removal/session loss.

Retain source drop-versus-picker acceptance and the add-control cap of ten, not an invented hard multi-pick/server cap. Restore server drafts without auto-selecting a restored language. Uploaded-without-duration stays preparing and follows `poll_interval_ms`/five-minute timeout. Selected language and translation target must be written again, in order, before the job-id start request; returning to transcription clears translate_to. Wait for that write, never run option writes and Start concurrently. Only successful start navigates to the first job and adopts the returned balance facts. No blind POST replay after an ambiguous response; read known job state before presenting a user retry.

YouTube uses metadata/add then its dedicated resolver, including source language defaults, round-versus-ceil display distinction, caption errors and source failure draft removal. A queue containing YouTube follows the source resolver branch; do not invent mixed file/YouTube batch support or convert it into ordinary paid audio transcription. Missing captions offers the existing download-and-upload guidance, not an automatic paid fallback.
