# P8-IMPL-3: `transgate-native`, `transgate-cli`, `transgate-tui` (p1W)

Status: source-ready, built and tested locally; not yet run against the owned product runtime (Y's D14 gate). No git writes.

## Crates

| Crate | Path | What it is |
|---|---|---|
| `transgate-native` | `transgate/native` | What the terminal shells share: `Vault` (D8: OS keyring via `keyring 4.2`, or a 0600 JSON file named by `TRANSGATE_SESSION_FILE` for headless machines and tests), `TerminalPorts` (the FFI `NativePorts`: keyring storage, `pick(path)`, `ffprobe` measure or `None`, a streaming PUT with whole-percent progress and the file's declared type, `save` into an out dir), `Loopback` (D7: RFC 8252 one-shot 127.0.0.1 listener; only a request whose target core's `route::parse` says carries a `code` or an auth error ends the wait), `Shell` (wraps `transgate_ffi::TransgatePresenter`; `wait(timeout, |&AppVm| Option<T>)` over a condvar `Signal` the view listener wakes), `HostConfig::from_origin` (`{origin}/api`, `{origin}/auth/v1`), `browser::open`. |
| `transgate-cli` | `transgate/cli`, bin `transgate` | clap commands `login [--email --password-stdin | --google [--no-browser]]`, `logout`, `whoami`, `upload <files> [--language --translate-to --speakers]`, `youtube <url>`, `jobs [--all --limit --json]`, `show`, `transcript <id> [--translation --json]`, `export <id> [--all-formats --out]`, `delete`. Each drives the presenter headlessly: dispatch intents, `wait` until the view says it is done, print what the VM holds. |
| `transgate-tui` | `transgate/tui`, bin `transgate-tui` | ratatui shell: `ui.rs` pure state + `update(&mut UiState, &AppVm, KeyEvent) -> Vec<Action>`; `view.rs` render functions over sub-VMs; `host.rs` executes actions through `Shell`/`TerminalPorts`; `run.rs` the terminal loop with a restore-on-every-exit guard (plus ratatui's panic hook). Colours only through the generated `design_tokens.rs` (`Tokens::tone`). |

Workspace: both new crates and `transgate/tui` are registered in the root `Cargo.toml`. Cargo.lock sha256 `10f03d17…9550e` (adds keyring 4.2.0 + keyring-core 1.0.1 + zbus-secret-service-keyring-store 1.0.1, rpassword 7.5.4, assert_cmd 2.2.2). `[lib] doctest = false` on native/cli/tui: `transgate-ffi` is lib+cdylib+staticlib and rustdoc is handed an rlib path cargo never produces (no doctests exist in these crates).

## Core and Shells

- No business `if` in either shell: enablement (`start_disabled`, `download_enabled`, `can_load_more`), confirmation (`confirm_delete`), tones, labels, errors and alerts all come from VM fields. The only core change: `upload_queue::Alert::{title, paragraphs}` carries the alert copy keys the web `UploadAlerts.svelte` rendered inline, so the terminal shells render the same catalog keys.
- All copy through `transgate_i18n::translate` (strict). A missing key shows as `ns.key` (a visible bug, not a fallback language). The TUI test `every_hint_label_of_every_screen_is_a_catalog_key_in_all_locales` pins every hint label to an existing key in all 16 locales; keys without a catalog word show the key glyph only. Usage text (`--help`, the TUI `USAGE` line) is developer syntax, not product copy.
- Google sign-in (D7): one presenter at `/home` with `site_url` = loopback origin sends `Auth(GoogleChosen)`; core asks the platform to `leave(url)` (opened, or printed with `--no-browser`); the loopback returns the callback target; a second presenter is started at that target and core exchanges the PKCE code on `Started` with the verifier from the vault. No auth rule is repeated in the shell.
- Exit codes (D13): 0 ok; 1 domain refusal (an alert, no lines, not ready, a keyring/save failure); 2 usage (clap, bad locale/language, missing file); 3 auth (no session, invalid credentials, bad/expired code); 4 network (`AuthFailure::{Network,Unavailable}`, `SESSION_UNAVAILABLE`, list/transcript load errors). `exit::auth_exit` maps the form's error `Msg`.
- `delete` reloads the list and waits for the row to be gone from the host's answer: core removes the row at once and has no completion signal for the host call (JOB-036), so the shell cannot otherwise tell a finished delete from one still in flight.

## Verification (run here)

- `cargo test -p transgate-native`: 8 (file vault round trip and 0600, corrupt-file error surfaced once, loopback answers only a code/error request with 200 and probes with 404, wait timeout, signal wake/timeout, origin derivation).
- `cargo test -p transgate-cli`: 1 unit + **14 actual-process tests** (`assert_cmd`, the built `transgate` binary) against a loopback axum host serving `/auth/v1` and `/api` (`tests/support/mod.rs`): password sign-in stores the session, `whoami` prints email and translated balance, `logout` clears it; wrong password exits 3 with the catalog message in `en` and `tr` (and the Turkish text differs); unreachable host exits 4 with `p5.auth.network`; no session exits 3; eight usage errors exit 2; **Google loopback**: `--no-browser` prints the authorize URL with a `127.0.0.1:<port>/home` redirect, a favicon probe gets 404, the callback gets 200, a good code signs in (session in the vault) and a stale code exits 3 with `invalid_or_expired_code` and no session; jobs listed newest first as text (translated `COMPLETED`) and JSON, `--limit`; transcript with translated `Speaker 1:` labels and `[time]`, Turkish translation by name and by code, a missing translation exits 1 with `No transcript lines available`, a running job exits 1 with the loading message; export saves `wysiwyg` then `all_formats` zips and a bad out dir exits 1; delete reaches the host; upload creates the draft with the speaker flag, PUTs 11 bytes as `audio/mpeg`, sends `language: Turkish` options and starts the job; translation upload sends `translateTo`; an `insufficient_balance` 402 exits 1 with `Alert::Balance` title and paragraphs; YouTube add + resolve prints the job and a bad URL exits 1.
- `cargo test -p transgate-tui`: **89** (config parsing; exit mapping; reachability; 36 key-to-action tests including no-ops on the wrong screen, Ctrl-C everywhere, the delete confirmation owning the keyboard, the path prompt; 36 `TestBackend` render tests over `fixtures::*` VMs: translated status and tone colour from `Tokens`, light vs dark tokens, sign-in form never shows the password, errors in the error token, RTL right alignment, freemium fades, spinner frames, alerts, hints; a `tr` test and the all-16-locales hint-key test; one `run::step` test).
- clippy `-D warnings` clean on export, native, cli, tui. Smokes: `transgate-tui` with no `TRANSGATE_HOST` → usage + exit 2; with an unreachable host → `SESSION_UNAVAILABLE` text, exit 4; `transgate login` against a closed port → `p5.auth.network`, exit 4.

## Not proven

- No run against the owned product runtime (real GoTrue, real signed URLs, real `ffprobe` durations): Y's D14 gate.
- No pty test of the TUI loop (D14 excludes it); the event loop was exercised only through `run::step` with a `TestBackend` and the two process smokes above.
- The OS keyring backend (`keyring::Entry`) was not exercised here (tests use the file vault); a keyring refusal is surfaced as exit 1 after sign-in through `Vault::take_error`.
- `browser::open` (`xdg-open`/`open`) is not exercised; `--no-browser` is.
