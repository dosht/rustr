## Taskr API published before shell wiring

All routes use the existing verified identity and `/api/audio-work` account barrier. A request cannot select an owner. Ordinary work/upload routes and their JSON shape remain unchanged. Summary routes are additive: saved reads remain available without a provider, while start requires real LLM configuration. There is no Transgate consent/quota policy in taskr.

- `POST /api/audio-work/{work_id}/summary/generations`: JSON `{ "request_id": "<uuid>", "external_processing_accepted": true }`. Requires an owned completed work with transcript, and the explicit disclosure acknowledgment. New generation: 202; exact request replay: 200 with the same generation (never another provider call). Response is the generation snapshot DIRECTLY, not `{generation: ...}`. Reusing a request id for another work/operation/payload: 409. An explicit retry uses a NEW request id, not a replay. Disconnect never starts or cancels generation.
- `GET /api/audio-work/{work_id}/summary`: JSON `{ "summary": null, "generation": null }` initially. `summary` is the latest committed completed artifact `{ "generation_id": "<uuid>", "work_id": "<uuid>", "source_revision": 1, "text": "...", "saved_at_us": 123 }` or null; `generation` is the latest generation snapshot (including active, interrupted or cancelled) or null. This is the reload/discovery endpoint; no start is needed to discover/watch existing work. A new active generation does not hide the last completed summary. Completed summary survives transcript-only retention; account erasure deletes it in the existing atomic transaction.
- `GET /api/audio-work/{work_id}/summary/generations/{generation_id}`: owner-scoped generation snapshot. Fields: `generation_id`, `work_id`, `execution_id`, `source_revision`, `status`, `sequence`, `text`, `durable`, `remote_outcome_unknown`, `error`. Statuses: `accepted`, `running`, `completed`, `interrupted`, `cancelled`. `completed` means summary and generation completion committed atomically. Error is null or an explicit interruption reason; no provider credentials/prompts/input in a public snapshot. Text is cumulative plain text, not HTML.
- `GET /api/audio-work/{work_id}/summary/generations/{generation_id}/watch?after=<sequence>`: authenticated SSE attachment/reconnect to the SAME generation, never dispatch. Current authoritative snapshot is sent first, then bounded updates, then terminal. Uses `llm_http::encode_frame` directly: shared `event:text` application frames, no host-specific envelope. Identity is generation UUID, source revision, consent epoch 0, execution UUID. Resume with the reducer's `durable_seq`, not `last_seq`: transient outage/auth controls do not invent a DB watermark. Replacements may skip sequences and remain replacement-mode forever; a trimmed checkpoint `Hello` is replaced by final `Hello world`, never suffixed with raw `world`. Terminal partial text is retained in interrupted/cancelled snapshots; GET supplies detailed error/remote-outcome metadata.
- `POST /api/audio-work/{work_id}/summary/generations/{generation_id}/cancel`: no body. Returns the current generation snapshot; idempotent. Fences subsequent content writes and stops local consumption, not proof of provider cancellation/deletion. Terminal completed result is not erased by cancellation.

Errors use existing `{ "error": { "code": "...", "message": "..." } }`. Missing/non-owned work/generation: 404. Erased account: 410 `erased`. Work without an available completed transcript: 409 `not_ready`. Missing disclosure: 400 `invalid`. Conflicting request id/active source generation: 409 `conflict`. LLM not configured: 503 `not_configured`; real storage/provider availability remains explicit, never a fabricated summary.

Existing `GET /api/audio-work` returns `{ "works": [WorkView] }`; `GET /api/audio-work/{id}` returns `WorkView` directly. `WorkView` fields are `id`, `name`, `status`, `language`, `attempts`, `transcript`, `error`, `created_at_us`, `completed_at_us` (see `crates/taskr-work/src/http.rs`). Summary start/read-generation/cancel return the same generation snapshot directly. Use `Authorization: Bearer <existing session token>` on every request and SSE attachment. No provider key reaches the shell. Deterministic owned completed-work fixture source: `scripts/p4-fixtures/taskr-completed.sql` (owned disposable DB only; pass the enrolled session account and work UUID through psql variables).
