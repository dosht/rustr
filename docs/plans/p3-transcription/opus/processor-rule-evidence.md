### Production correction and preserved contracts

Root cause: `Tool::cleanup` previously deleted only files already named in the session snapshot, then removed the session. Detached workers/children were unowned by cleanup; their future encode/trim/thumbnail paths could be created after success was reported.

Repair verified by the lead's artifact-562 run:

- `transgate/processor/src/families/mod.rs`: per-session worker registration, cancellation senders and join handles. Registration and closing share one mutex; missing/closing sessions cannot dispatch new work. Closing removes presentation state immediately, signals all workers, waits for their completion/reaping, then removes known paths and the exact minted session-id file namespace (including future trim parts, thumbnails and superseded outputs). Concurrent cleanup requests await one completion. Detached cleanup survives a dropped request, so cancellation cannot abandon the fence.
- `transgate/processor/src/media.rs`: session worker scope supplies cancellation to the existing captured-output/sibling and streaming-progress process machinery. Already-cancelled work never spawns another probe/encode. Active children are killed and awaited; `Ended::Cancelled` is separate from timeout/error. No shell or process-wide kill in production.
- Seven family processing launch sites plus convert-video's background thumbnail are registered. Convert-audio retains synchronous completion via its result channel; the six detached families retain 202, busy 409 and existing allowance ordering. A cancelled synchronous encode retains the existing processing-failure 500, while a dispatch fenced before it starts returns expired 410. Invalidated state cannot be recreated by worker `Store::update`.
- Obsolete `store::cleanup` was removed after migrating its sole caller. Lead's multipart `State`/`FileSink`, waveform carry/as_chunks, UTF16 and compact error changes were left intact.
- Shared cleanup now removes superseded outputs for the same id too. H06 no longer expects the old replaced MP3 orphan to remain after Opus download. This is resource lifecycle cleanup; media response payloads/options/quotas remain unchanged.

`transgate/processor/Cargo.toml` adds only a dev-dependency feature on the existing Tokio version (`test-util`). No lockfile or runtime clock API was added.
