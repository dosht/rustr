## Frozen shared seams

1. **Identity and units.** Account ids remain UUIDs, Transgate job/line ids remain source-compatible signed database ids, attempt/claim identities are independent UUIDs. Instants are explicitly UTC microseconds; provider duration is explicitly milliseconds; source minute rounding remains a product decision. Reuse existing billing types at the billing boundary, never make shared media depend on billing or a host.
2. **Storage.** `ObjectRef` identifies store kind, bucket, key and optional generation/version. Temporary signed access carries the object reference, URL and expiry, never replaces persisted object identity. Source/provider access is distinct from a customer's callback URL. Secrets and signed URLs have redacted debug/error output. Storage ports cover signing, controlled external fetch/upload, lookup and deletion, including legacy Supabase targets; unsupported/retained/unavailable is not success.
3. **Transcription.** Shared `Transcriber` accepts a request with server-selected provider/model/language, optional translation target, signed audio access, attempt identity, source client reference and authenticated callback specification. Submission is explicitly accepted, definitely rejected or uncertain. Result observations carry provider/project/remote identity, observation origin and the duration actually received on that path. Preserve the full provider result needed by the pure normalizer rather than dropping token/paragraph/translation distinctions. Provider-specific pure payload DTOs belong to media-ports; HTTP behavior belongs to media-adapters. No business job status enters these crates.
4. **Result origin.** `ObservationOrigin` distinguishes webhook from recovery poll. Soniox webhook duration remains optional as received; a verification GET cannot fill it for billing. Deepgram payload must survive durable intake until application. The adapter never decides minutes, refunds, fallback, completion or retention.
5. **Host transaction.** Jobs persistence opens the transaction and attaches the existing billing transaction seam. Begin with account locks (capacity lock precedes them only when claiming submission), then ascending job ids and fresh facts. Lifecycle saves compare revisions; user line edits remain LWW/update-only. Explicit app commands own start-batch, submission claim/ack, result ingestion, line/speaker edits, soft/hard deletion and retention. Network never occurs inside the transaction. Deferred debit failure uses the existing savepoint boundary without rolling back delivered lines/completion.
6. **Attempt/inbox identity.** Attempt records retain provider/project, claim token/expiry, request facts, current/superseded remote identities and uncertainty. Durable callback intake authenticates and binds identity before duplicate handling. Conflicting payload is not replay success. Callback completion never takes the capacity lock. One local terminal application/charge is guaranteed; remote exactly-once is not.
7. **Erasure.** A durable barrier and resource manifest precede cascade. Billing's erasure operation discovers the union of affected owners before any owner lock, locks sorted and rechecks. The barrier covers provisioning, billing callbacks, directory refresh, worker intake, signing and edits; it survives completed cleanup. Account erasure stops future verified subscription charges under D10 before claiming completion. Its narrow gateway cancellation method is distinct from ordinary manual-support cancellation. Preserve D5 financial data behavior and report retained/blocked external resources honestly. Taskr invokes the same billing and media seams for its explicitly enrolled audio-work resources.
8. **Scheduling.** media-postgres exposes only dedicated-connection advisory locking and durable UTC schedule-slot claiming; no generic workflow engine. Product code owns schedules, predicates and retry policy. Persistence owner publishes the concrete APIs to core/host owners as soon as the source interfaces exist.

Owners may choose private helpers and the exact source-derived payload fields. Publish public Rust signatures promptly to dependent owners; incompatible interface changes require a direct coordination message, not parallel guesses. Follow current async `BoxFuture`/port and SQLx conventions. Do not add generic commands, plugin frameworks, compatibility aliases or unsupported provider defaults.

## Required consumer behavior

Transgate implements the captured upload/URL/YouTube paths, twelve statuses, provider routing/recovery, translation, transcript edits and exports, retention settings/sweeps and account-erasure saga. All 61 language choices, 53 translation targets and sixteen locale identifiers remain represented. Source LWW edits, Soniox observation-origin money and pin-first compatible fallback are settled. External URL fetching must enforce destination/redirect checks and controlled staging; a validation HEAD alone is not SSRF containment. Public YouTube captions do not silently use the paid signed-in adapter.

Taskr audio-work is a small real second consumer: upload, two-provider fallback, restart/lease recovery, retention and erasure over its own aggregate. It shares the verified pool/database with taskr billing and its enrolled sample, separate from Transgate. The sample gains a narrow barrier-fenced erasure hook so account deletion does not leave its customer/work rows behind. Ordinary tasks remain unmetered; no taskr-core dependency changes, scanners, workspace-transfer policy or extra third-party products.

Free tools remain server-first and separately deployed. The processor owner ports all 39 tool endpoints plus health, source session/download/ZIP/thumbnail/progress behavior and ten-minute cleanup. P5/P6 own their rendered pages, not the runtime. It must be runnable against tiny locally generated media fixtures.

## Evidence and handoff

Write domain regressions before the corresponding rules. No agent runs builds, tests or formatters mid-flight; the lead runs the integrated checks once source owners report ready. Use real local HTTP servers/processes and PostgreSQL, not assertions that only echo inputs or inspect source. Each owner supplies exact commands, env names, rule/defect ids, source-derived fixture provenance and unresolved clauses, without marking the canonical ledger green.

Required regressions include two-process capacity/owner races, superseded callbacks, unknown-duration debit rollback, all affected-owner erasure locks, stale credentials after completed erasure, expired PUT recreation, provider-origin duration, source LWW edits and real restart/delivery. Exercise actual binaries and FFmpeg before claiming completion. Do not call fixtures live provider acceptance.

Their P2/global gates remain strict until those consumer clauses are exercised.
