Agreed with Opus w23:p1X after cross-critique, including the precision corrections acknowledged in its final reply. This contract supersedes conflicting independent-proposal positions. Lead approves the implementation contract and assigns visible owners. No implementation or verification was performed during this review.

1. **Scope accounting.** Preserve all 526 final rules and every parity obligation. Track each mixed row's P3 and later-phase clauses with executable evidence and decision references. A phase command may report local readiness; it cannot weaken global gates, certify an unfinished clause or relabel fixtures as live acceptance. Keep all 61 transcription languages, 53 translation targets, 16 locales and twelve statuses. RunPod/health retirement is explicit and does not discard imported data.

2. **Boundaries.** `transgate/core` owns product Job/routing/transcript/edit/export/privacy/presentation logic and `languages.rs`. A Transgate PostgreSQL adapter owns one transaction and its own SQLx history; HTTP/server and export-byte adapters remain thin. Shared `media-ports` and `media-adapters` contain protocol value types and real Soniox/Deepgram/storage transports only. A small shared PG lock/slot adapter has no workflow engine. No host dependency enters billing or the shared transports.

3. **Taskr.** Explicit audio-work sample in `crates/taskr-work`, its own aggregate, separate database, same real protocol adapters and lock/slot adapter. It proves upload, two-provider fallback, long-running work, restart/lease recovery, retention and erasure, including the billing account-erasure extension. Scope deletion to the explicit sample enrollment/resources; do not invent taskr workspace-transfer policy. Existing taskr billing sample contract and ordinary task creation remain unchanged; no `taskr-core` dependency/change, scanners or new third-party products.

4. **Atomic jobs.** READ COMMITTED, account first, ascending host job ids, fresh facts, revision-checked lifecycle saves. Submission capacity lock precedes this order only for claims; callback completion never acquires it. No network inside a transaction. All batch charges, transitions and submit work commit together. Preserve UPDATE-only debit and zero-minute P2 semantics. Use saved `release_subject_charges` first for single-subject hard deletion. P2 repair/outbox isolation remains its existing owner and gate scope.

5. **Attempts and recovery.** Persist claim, attempt identity, request facts and lease before HTTP. Fence stale acknowledgements and callbacks. Retain enough old-attempt remote identity for conflict detection and erasure; overwriting one remote-id column must not orphan superseded work. Soniox keeps source `client_reference_id=job_N`; reconciliation additionally matches the attempt parameter in returned `webhook_url`, submitted audio URL and creation time. No match or multiple matches stays unresolved; a listing miss is not proof of nonacceptance. Changing the reference format needs a recorded correction. Deepgram stuck resubmission can buy duplicate remote work; promise exactly-once local application/charging only. Preserve configured duration threshold, source queue ordering/spacing/capacity and existing retry-count meanings, including no invented Deepgram terminal retry cap. Persist and reclaim interrupted schedule runs instead of letting a unique slot strand work forever.

6. **Routing.** A compatible stored pin is the first attempt as source; it does not disable fallback. Removed RunPod counts as unavailable; when fallback is enabled, try compatible candidates. Otherwise use configured non-translation long/qta overrides, valid preference, Soniox then Deepgram. Translation and auto-detect remain Soniox-only. Through a recorded correction, an incompatible pin becomes a failed first attempt, then compatible fallback when enabled, otherwise job failure; it is not immediate rejection of the job. Replace unconditional Soniox last resort with pending for capacity shortage or explicit incompatibility failure. Apply capacity accounting to claimed and uncertain live attempts as well as running jobs. Preserve the account-specific Nova-2 exception as trusted host configuration. Imported running work needs explicit cutover handling, not silent fresh routing.

7. **Callbacks and money.** Mandatory authentication and exact provider/project/attempt/remote-id binding precede duplicate handling. Commit authenticated intake before 2xx. Soniox inbox stores id/status/attempt, optional `reported.audio_duration_ms` as received and observation origin; Deepgram retains result body until commit. Webhook billable duration is positive received duration, otherwise max token end; a verification GET cannot enrich it. Recovery retains its poll-origin observation. Normalize into internal `metadata.duration_ms`, then use existing minute rules. Unknown-duration debit is strict inside a savepoint; charged/refused/no-duration or storage-error outcome commits with lines, completion and outbox. Known lower duration changes duration only; higher does not increase it. A replay never charges again. Transient ingestion failure retries; deterministic failures stay coded. YouTube remains uncharged.

8. **Editing.** Preserve source last-write-wins without required expected line revision or new stale-edit 409. Empty text and edits of any retained owned status remain allowed. Internal account/job locks and update-only existing-row writes prevent resurrection after retention/erasure. Speaker rename is atomic. User edits cannot be overwritten by provider replay. Optimistic user editing is a separate mu decision.

9. **P3 billing erasure extension.** One combined first billing operation discovers the union of owners affected by account-attributed usage, all erased subjects and account-owned packages, locks sorted, rereads the owner set and conflicts/retries on change. Delete signed imported cross-owner usage/legacy rows, then source-required account-owned billing rows, and detach retained billing-info/invoice references according to the recorded policy. Surviving balances derive from the remaining usage (BIL-003); there is no persisted balance or package-sum update. Do not loop single-subject release or expose unrestricted SQL through a host escape hatch. Add narrow runtime permissions and import-role separation with negative authority tests. Both consumers call this extension; its absence is P3 work, not a newly invented P2 BIL failure.

10. **Erasure barrier and resources.** Establish the barrier and manifest before local cascade; retain it after closure. Provisioning rechecks inside the locked account transaction before any grant. Intake, workers, directory refresh, signing, edits and archival all honor it. Delete Supabase-owned `jobs` artifacts via Storage API before GoTrue where required; do not mistake GCS/R2 audio for all artifacts. Track every attempt/object, late-bound identity, diagnostic body and outstanding PUT expiry; re-sweep after capability expiry. Blocked/retrying/unresolved steps remain runnable. Only confirmed/absent resources, or explicitly approved exceptions, can finish; exceptions never mean fully erased. UUID tombstones are pseudonymous, not anonymized. No new telemetry/payment-provider erase call or subscription cancellation policy is silently introduced.

11. **Retention/storage.** Completed lines only, true cleanup preference, inclusive `now - days - 1 day`, default cron argument 30, 02:00 UTC; null/false keep and unlimited history does not exempt. Lock candidate accounts/jobs then reread preference, count and delete atomically; above100000 aborts without deletion. Dry-run has identical predicates and no audit writes. Commit run initiation, success with deletion, and failure/skip/abort after rollback; recover interrupted runs. Weekly history uses the same source extra-day arithmetic. History UI uses supplied calendar/time-zone context, separate from cleanup. Store object references, source paths and temporary URLs with source TTLs; record generation where supported, no mandatory copy/staging layer. GCS retention blocks early deletion; provider behavior and deployment lifecycle remain evidence requirements.

12. **Actual composition/evidence.** Restricted real pools, JWT/dev-auth boundaries, trusted signup/contact integration, two-process races, real HTTP loopback transports, actual binary restart and mail outbox delivery are required. Keep stable target keys and host namespaces; no fake sink or test-only producer counts as delivery. Tests must cover changed callback duration origin, LWW races, deferred-debit storage rollback, owner-union deadlocks, completed-saga stale JWTs, superseded attempts and expired PUT recreation. Fixture language serialization is not live provider acceptance. Latest-snapshot migration and deployed storage/provider evidence stay unproved until actually obtained with authorization.
