## Actionable findings

1. **P2: Supabase object-info parsing uses user metadata as storage metadata (D2, PRV-035).** `crates/media-adapters/src/storage.rs:188`, `LegacySupabaseStorage::head`, selects `value.metadata` at line 194, then requires its `size`. The official [Supabase InfoRenderer](https://github.com/supabase/storage/blob/master/src/storage/renderer/info.ts) returns `size`, `content_type` and `etag` at the root; `metadata` is `obj.user_metadata`. A normal response with root `size:5` and `metadata:{}` or `metadata:null` fails with `legacy object size`; custom user metadata can instead supply a false size. The existing D2 fixture uses the invented nested shape. This breaks real legacy object lookup and the positive lookup used during deletion reconciliation, although it fails closed rather than falsely completing that reconciliation. **Required fix:** parse the object-info root fields separately from user metadata; add official-shape fixtures with empty, null and misleading custom metadata. Keep authenticated absence and failed lookup distinct.

2. **P2: Public captions lose the source's bounded web-player fallback (UPL-029/038).** `crates/media-adapters/src/captions.rs:143`, `PublicYouTube::fetch`, propagates every InnerTube error before trying the watch page. The captured dependency `/home/mu/Business/Transgate/frontend/node_modules/youtube-transcript/dist/youtube-transcript.esm.js:30-57` calls `fetchViaWebPage` when `fetchViaInnerTube` returns undefined, including non-2xx, network errors and malformed player JSON. Counterexample: InnerTube returns 500, but the watch page advertises a working public caption track. Source succeeds; this adapter returns an error. The handoff documents the narrower behavior, but the frozen decisions do not approve this parity reduction. **Required fix:** retain the source's single bounded discovery fallback for those primary-player failures, with destination checks and no paid-service fallback. Add a primary-failure plus valid-web-track fixture; this is not an unbounded retry loop or product provider failover.

Transport owner confirmed both findings. No deployed fixture supports nested object-info metadata; `tests/storage.rs:97-98` supplies that synthetic shape and asserts only `is_err`, so a parse error can falsely satisfy the intended deletion-reconciliation check. Require the expected unconfirmed-deletion outcome rather than any error. The owner also confirmed that the caption restriction documented in PROVENANCE and the handoff was an implementation choice without an approved parity decision. No automatic changes or checks were requested or performed.
