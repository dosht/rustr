# Web app screens and user flows

The signed-in app is a transcript master/detail workspace with separate touch-phone views.
Settings, purchase, invoice history and API-key management sit beside that workspace.
Disabled dashboards and prototypes are recorded as such, not promoted into new features.

## Inventory

Paths are relative to the Transgate repository. Inventory is source inspection, not a production browser run. Historical findings were retained selectively and checked against the current source. In particular, upload selection persistence and export options have changed since older notes.

### Elements, states and step order to preserve

- Upload: choose files or YouTube, show queue rows and progress, choose mode/language and speakers, submit, then navigate to the created job. Desktop puts mode tabs above the drop zone and configuration after files. No grammar or price-estimate control is present in this workspace. Phone uses large source buttons, language sheets, a total-duration line and a fixed submit button. Sources: `frontend/src/features/transcription/ui/TranscriptionWorkspace/TranscriptionWorkspace.tsx:183-275`, `frontend/src/features/transcription/ui/mobile/MobileNewTranscript.tsx:181-315`.
- Upload states: initializing/restored drafts, empty, uploading, preparing duration, ready, failed, submitting, missing language, insufficient balance, YouTube resolution failure and five-minute preparation timeout. The submit gate requires every file uploaded with a non-null duration. Draft language is deliberately not restored. Current code persists chosen source/target again before submission, so the old selection-write race is not recorded as an unfixed defect. Sources: `frontend/src/features/transcription/viewmodels/useTranscriptionViewModel.ts:257-285,378-454,496-520,961-1052`.
- File-source buttons are upload, microphone, YouTube, Google Drive and OneDrive. Only upload and YouTube are generally enabled today. A generic URL field is not offered in the current workspace. Direct URL submission is an API flow owned by jobs/API discovery. Sources: `frontend/src/features/transcription/ui/TranscriptionWorkspace/TranscriptionWorkspace.tsx:241-251`; `frontend/src/utils/featureFlags.ts:43-54`.
- Transcript desktop: sidebar, fixed title/player header, transcript/AI-analysis tabs, resizable Ask AI panel. Phone: transcript/analysis/chat tabs, swipe navigation, sticky audio player and action sheet. YouTube uses dedicated embedded-player layouts. Sources: `frontend/src/components/Transcript/Transcript.tsx:634-860`; `frontend/src/features/job-management/views/mobile/MobileJobDetailsView.tsx:168-254`.
- Transcript states: waiting, preparing, running, speaker labeling, completed with no lines, failed job badge, line-fetch error, switching-job skeleton, freemium fade/upgrade and missing audio. Timestamps seek playback; active lines track playback. Pencil edits pause playback; Enter saves and Escape cancels. Speaker label selection changes a line; speaker rename changes the job's matching labels. No dedicated transcript-search control was found in these active views. Sources: `frontend/src/features/transcriptLines/containers/TranscriptLinesContainer.tsx:150-235,309-353`; `frontend/src/features/transcriptLines/views/TranscriptLinesView.tsx:135-205`; `frontend/src/components/SpeakerLabel/SpeakerLabel.tsx:201-224`.
- Translation is selected before submit, with source and target different. Normal users see translated text; original-language tabs require SHOW_ORIGINAL_TRANSCRIPT. Sources: `frontend/src/features/transcription/viewmodels/useTranscriptionViewModel.ts:819-878,969-1008`; `frontend/src/features/transcriptLines/viewmodels/useTranscriptLinesVM.ts:77-114`; `frontend/src/utils/featureFlags.ts:55-64`.
- Export: primary download creates a ZIP with full text TXT and a Word document (stored as `.doc`), SRT/VTT for video sources, and CSV when speakers exist. Word output follows timestamp/speaker toggles; all-formats forces subtitle inclusion. Translation callers filter to translated lines. Phone currently omits toggle options when calling the saver and has no all-formats handler. Sources: `frontend/src/utils/transcriptFileSaver.ts:19-98,101-170`; `frontend/src/components/Transcript/Transcript.tsx:311-328`; `frontend/src/features/job-management/views/mobile/MobileJobDetailsContainer.tsx:108-118`.
- AI: consent introduction and accept/decline gate precede content. Opening analysis generates once when consent and lines exist; cache/loading/streamed sections/success/error/interrupted/retry are visible. Highlights are analysis content, not a separate mounted product tab. Chat streams responses, displays usage limits, supports copy/retry/rating and export. Sources: `frontend/src/components/AIFeatureWrapper/AIFeatureWrapper.tsx:9-33`; `frontend/src/components/Transcript/Transcript.tsx:250-301`; `frontend/src/features/aiAnalysis/views/desktop/DesktopSummaryView.tsx:149-272`; `frontend/src/features/aiAnalysis/views/desktop/DesktopChatView.tsx:172-309`; `frontend/src/hooks/useChatLimits.ts:41-143`.
- Job list: desktop table has name/status/duration/date/actions, infinite scrolling, view/download/feedback/delete. Phone adds filters, cards, swipe delete and pull-to-refresh. Delete requires confirmation and removes the job from the view. Sources: `frontend/src/features/job-management/views/JobListTable.tsx:163-175,247-282,429-467`; `frontend/src/features/job-management/views/mobile/MobileJobListView.tsx:1`.
- Settings: profile shows email/joined date, theme and language; AI consent can be granted/revoked; subscription shows package/payment and cancellation; manage data controls monthly deletion, transcript-retention opt-out, delete-all and delete-account confirmations. Account deletion calls the data-management action then `/api/delete-account`, followed by centralized logout. Sources: `frontend/src/features/settings/views/tabs/ProfileView.tsx:38-79`; `frontend/src/features/settings/views/SettingsView.tsx:111-156`; `frontend/src/features/settings/containers/SettingsContainer.tsx:84-89`; `frontend/src/features/data-management/views/ManageDataView.tsx:1`.
- Balance is read from the user balance view and refreshed every 30 seconds; account menu opens purchase/settings/support and API keys. There is no enabled usage-analytics dashboard. Feedback records a rating and optional comments in job_feedback; support posts a message plus job context. Sources: `frontend/src/components/Balance/Balance.tsx:15-46`; `frontend/src/components/UserArea/UserArea.tsx:159-267`; `frontend/src/components/FeedbackModal/FeedbackModal.tsx:86-118`; `frontend/src/components/SupportModal/SupportModal.tsx:14-48`.
- First visit: `_app` mounts SimpleSignInPopup, CookieConsent, LandscapeBlocker and global providers. The actual popup is homepage-only, desktop-only, delayed two seconds, with Google sign-in and dismiss. It is not the similarly named AutoSignInModal implementation. Sources: `frontend/src/pages/_app.tsx:43-80`; `frontend/src/components/SimpleSignInPopup.tsx:14-71`.

### Rules seen in UI code

Business ownership stays outside this file. Preserve these observations as cross-references, not duplicate rule IDs:

- UPL/JOB: ten-file add-control cap, readiness gate and duration timeout: `frontend/src/features/transcription/viewmodels/useTranscriptionViewModel.ts:137,257-270,496-520`. The cap hides the add control; it is not evidence of a server limit.
- UPL/TRL/LNG: explicit language selection, transcription auto-detect, source/target conflict clearing and submission persistence: `frontend/src/features/transcription/viewmodels/useTranscriptionViewModel.ts:193-205,819-878,969-1008`.
- BIL/FRE: balance errors become an upgrade modal, no browser price quote in the active upload view: `frontend/src/features/transcription/viewmodels/useTranscriptionViewModel.ts:1038-1046`; `frontend/src/features/transcription/ui/TranscriptionWorkspace/TranscriptionWorkspace.tsx:183-275`.
- FRE/EDT/EXP: duration above 20 minutes triggers the freemium banner but visible transcript lines extend through start time 22 minutes: `frontend/src/features/transcriptLines/containers/TranscriptLinesContainer.tsx:309-335`. Backend worker owns reconciling display versus API/export bounds.
- PRV: history and retention preferences belong to privacy/identity; list queries apply history filtering in `frontend/src/dao/JobRepository.ts:151-157,191-197`.
- AI/PRV: consent and chat quota display are not authorization substitutes: `frontend/src/components/AIFeatureWrapper/AIFeatureWrapper.tsx:9-33`; `frontend/src/hooks/useChatLimits.ts:41-143`.
- IDN/FLG: blocked-user and privileged-user outcomes remain identity/server concerns. Special-client display and flag allowlists must not become unrestricted shell-only entitlements: `frontend/src/pages/home/[[...jobId]].tsx:211-219`; `frontend/src/utils/featureFlags.ts:122-180`.
